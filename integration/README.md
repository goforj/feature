# Integration tests

Run `make test-integration` from the repository root with Docker available. The suite starts one digest-pinned GO Feature Flag relay and one official LaunchDarkly Relay Proxy per package run. It verifies both running versions and terminates containers after the tests, including partial startup failures. Testcontainers also owns host-forwarding helpers and its resource reaper. Missing Docker is a failure, never a skip. Tests use fake keys and isolated flag namespaces; no hosted credentials are loaded.

The shared ten-case contract runs against native memory, the official LaunchDarkly SDK through the real Relay container, OpenFeature with the LaunchDarkly provider through that same container, and OpenFeature with GO Feature Flag in remote and in-process modes. It checks true, successful false, both missing-flag fallbacks, identity targeting, owned attributes, cancellation, concurrent decisions, live updates, and deletion followed by recreation. Update checks require a successful decision with an opposing fallback, so an outage cannot masquerade as adoption of a false value. Deletion must return ErrNotFound and each caller-selected fallback before recreation succeeds.

Additional tests exercise real file replacement and deletion, invalid-document retention, request snapshots during concurrent refresh, refresh-worker shutdown, typed remote targeting, real relay authentication and rejected initialization, malformed HTTP success, cancellation during an HTTP response, and in-process last-valid configuration. One test pauses and resumes the actual relay container to prove outage fallback and update recovery. A reverse proxy separately injects specific transport failures in front of that service.

LaunchDarkly Relay tests verify authentication and rejected SDK initialization, native configured off-variations, analytics forwarding after owned SDK close, and actual container pause/resume with cached decisions and update recovery. The container consumes FDv2 polling and streaming data from a local fixture using official SDK wire-model helpers. Application SDKs connect exclusively to the real container. All upstream service URIs, including analytics, point to the local fixture. Separate direct SDK protocol tests retain malformed-response, startup cancellation, interrupted-stream, and borrowed-client ownership coverage.

This exercises the official production Relay image without depending on a hosted account or its Enterprise offline archive workflow. The upstream fixture emulates the hosted data plane; the Relay itself runs unmodified. This does not establish hosted LaunchDarkly account, environment, or credential verification. [Relay configuration](https://github.com/launchdarkly/ld-relay/blob/v9.0.0/docs/configuration.md) documents its upstream URI settings.

Both LaunchDarkly adapters additionally evaluate multi-kind identities, numeric/boolean rules, and true off-variations through the container. Privacy tests inspect the forwarded analytics: the private email must be absent from every collected batch, its native redaction metadata must remain present, and an unredacted control must still reach the collector. Required version tests compare report metadata with the image pins and the SDK/provider versions actually selected by Go.

GO Feature Flag fetches complete JSON documents from a local HTTP fixture. Testcontainers opens forwarding tunnels after container readiness, so both services retry their initial upstream connections. Tests wait for actual flag visibility before asserting behavior. Service images and SDK/provider versions are pinned in [versions.json](versions.json) and module requirements.

`make record-integration` updates the tracked execution report only after the complete required suite passes. `INTEGRATION_RUN='TestDriverConformance/openfeature-goff-remote' make test-integration` runs a focused case and writes separate focused artifacts. It cannot overwrite full-suite evidence. Raw JSON events, coverage, and reports are under `.artifacts/`; [the tracked report](../docs/integration-results.json) records the tested source fingerprint and exact passed case count. Integration coverage is never merged into the unit coverage gate.
