Typed feature flags for Go, with targeted rollouts, live refresh, and consistent decisions within a request.

## What's included

- Boolean, string, integer, float, and structured flags with explicit fallbacks and decision metadata. Decode application structs and slices with ObjectAs.
- Exact identity and typed attribute targeting, named variants, weighted splits, scheduled rules, and progressive rollouts.
- Memory, file, HTTP, and custom sources. Complete valid documents publish atomically; refresh failures retain the last valid snapshot. Applications own refresh and shutdown.
- Captured native snapshots that preserve observer and tracking configuration.
- Optional direct LaunchDarkly and OpenFeature adapters, plus a native OpenFeature provider. Vendor SDK evaluation and lifecycle semantics remain explicit.

## Try it

```sh
go get github.com/goforj/feature@v0.1.0
```

Optional SDK modules:

```sh
go get github.com/goforj/feature/driver/launchdarklyfeature@v0.1.0
go get github.com/goforj/feature/driver/openfeaturefeature@v0.1.0
```

The root needs Go 1.24 or newer and has no external runtime dependencies. LaunchDarkly needs Go 1.25; OpenFeature needs Go 1.26. All three modules have independent v0.1.0 tags.

See the [quick start](https://github.com/goforj/feature/tree/v0.1.0#quick-start), [provider capabilities](https://github.com/goforj/feature/blob/v0.1.0/docs/capabilities.md), and [behavior contract](https://github.com/goforj/feature/blob/v0.1.0/docs/contract.md).

This initial release covers the standalone library and app-owned integration. Generated GoForj Feature components and hosted LaunchDarkly account verification remain separate. The [release verification record](https://github.com/goforj/feature/blob/main/docs/release-readiness.md) records module publication and application checks.
